# AniKot 2.0.2 — Low Memory Async

VK-бот для поиска аниме и дунхуа по кадру, фото и названию. Версия рассчитана на BotHost.ru, запускается через `main.py`, собственного Dockerfile не требует.

## Поисковые режимы

- **AniKot** — `gemini-3.1-flash-lite`.
- **AniKot Pro** — `gemini-3.5-flash`.
- **AniKot Pro+** — `gemini-3.1-pro`.
- В проекте больше нет внешнего каталога для перепроверки результатов: ответ формируется выбранной моделью напрямую.
- Минимальные пороги по умолчанию: 55% / 65% / 75%. Если результат ниже порога, AniKot всё равно показывает наиболее вероятный тайтл и до двух альтернатив, а запрос возвращает на баланс.
- Администраторы из `ADMIN_IDS` имеют безлимит всех трёх типов запросов.

## Формат результата

```text
Название: ...
Персонаж: ...
Страна: Япония/Китай
Год: ...
Количество эпизодов: ...
Уверенность: ...%
```

Под результатом только inline-кнопка `Назад`.

## Регистрация и документы

Перед первой регистрацией сообщение выглядит одной строкой:

```text
Продолжая регистрацию, вы принимаете Пользовательское соглашение и Политику конфиденциальности.
```

Названия документов кликабельны через ссылки из `USER_AGREEMENT_URL` и `PRIVACY_POLICY_URL`. Под сообщением только кнопка `✅ Согласен`.

После согласия бот спрашивает, есть ли у пользователя реферальная ссылка.

## Бонусы и рефералы

- Регистрация: **+1 обычный запрос AniKot**.
- Подписка на сообщество: **+2 обычных запроса AniKot** один раз.
- За приглашённого друга: **+3 запроса AniKot Pro** после 3-дневной проверки нового пользователя.
- Каждому пользователю создаётся индивидуальная ссылка `https://vk.me/<community>?ref=anikot_<token>`.
- Для постоянной базы рекомендуется `VK_REFERRAL_BASE_URL=https://vk.me/club<ID>`.

## Страйки за отписку

Бонус за подписку выдаётся один раз. Если пользователь получил его и затем отписался, начисляется страйк. **3 страйка = блокировка аккаунта AniKot**. Повторная подписка не сбрасывает страйки и не выдаёт бонус повторно.

## Контент 18+

Если обычный AniKot или Pro распознаёт adult-контент, списанный запрос возвращается и пользователю предлагается Pro+. Для adult-поиска Pro+ требуется подтверждение 18+. При признаках несовершеннолетнего или неоднозначного возраста запрос не обрабатывается и возвращается.

## Ошибки

Пользователь не получает технические сообщения, названия endpoint, коды HTTP, названия внутренних интеграций или настройки разработчика. В интерфейсе используются нейтральные сообщения вроде `Произошла ошибка. Попробуйте позже.` или `Запрос возвращён.`. Подробности остаются только в серверном логе.

## BotHost

- Главный файл: `main.py`
- Порт в панели: `3000`
- Домен: например `anikot.bothost.tech`
- Dockerfile: выключен
- `WEB_HOST=0.0.0.0`
- `PORT` вручную не создавать — BotHost передаёт его сам.

Проверка:

```text
https://anikot.bothost.tech/health
```

Ожидаемая версия: `2.0.2-bothost`.

## LAVA webhook

Webhook:

```text
https://anikot.bothost.tech/lava/webhook
```

Событие: `payment.success`. Ключ в webhook должен совпадать с `LAVA_WEBHOOK_KEY`.

Если товар с динамической ценой редактировался/перепубликовывался и старый `LAVA_OFFER_ID` стал недействительным, AniKot один раз пытается найти актуальный оффер по `LAVA_PRODUCT_TITLE` и повторить создание счёта. Для надёжности всё равно рекомендуется хранить актуальный `LAVA_OFFER_ID`.

## База данных

По умолчанию база хранится в `/app/data/bot.sqlite3`. Старая база v1.5.x совместима: миграция схемы не требуется, текущие балансы, оплаты, страйки, рефералы и регистрации сохраняются.


## AniKot 2.0 — снижение RAM

Версия 2.0 перерабатывает сетевой слой без изменения пользовательских балансов и SQLite-базы:

- все внешние HTTP-запросы выполняются асинхронно;
- AIAI, загрузка изображений и LAVA используют один общий `httpx.AsyncClient` и один connection pool;
- все три AI-режима используют общий глобальный лимит до 3 одновременных AI-запросов;
- VK-фото скачивается потоково на диск через `aiofiles`, а не целиком в RAM;
- выбирается подходящий размер VK-фото с максимальной стороной около 1280 px вместо крупнейшего оригинала;
- размер входного изображения ограничен 6 MiB;
- Base64 создаётся только непосредственно перед обращением к модели и освобождается сразу после запроса;
- SQLite cache ограничен, mmap отключён, временные таблицы направлены на диск;
- `uvicorn[standard]` заменён обычным `uvicorn`;
- access log Uvicorn отключён;
- после обработки изображения в low-memory режиме запускается сборка мусора;
- проверка созревших рефералов ограничена одним запуском в минуту;
- `/health` показывает текущий RSS процесса и число активных поисков;
- очередь ограничена `MAX_PENDING_SEARCHES=30`, чтобы всплеск входящих кадров не раздувал RAM.

Фактическое потребление RAM зависит от BotHost, размера кадров и числа одновременных поисков.


## 2.0.1 — работа с сомнительными результатами

- Модель больше не должна оставлять название пустым только потому, что сомневается.
- При низкой уверенности пользователь получает наиболее вероятный тайтл и до двух альтернатив.
- Низкоуверенный результат не расходует запрос: единица возвращается на соответствующий баланс.
- Пороги сделаны практичнее: AniKot 55%, Pro 65%, Pro+ 75%.
- Если модель вообще не смогла выделить тайтл, запрос также возвращается.


## 2.0.2 — списание только за успешный результат

- Поисковый запрос больше не списывается перед обращением к модели.
- Сначала AniKot проверяет наличие баланса, затем выполняет поиск.
- Единица списывается только если результат прошёл порог уверенности и будет показан пользователю.
- При низкой уверенности показывается наиболее вероятный тайтл и до двух альтернатив, но баланс не уменьшается.
- При ошибке, отмене, 18+ перенаправлении или отсутствии уверенного результата запрос также не списывается.
